# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

eAnalizer Mobile is a native Android app (Kotlin, Jetpack Compose/Material 3) that logs in to Enea eBOK, downloads hourly meter CSVs and analyses them like the Python [eanalizer](https://github.com/theundefined/eanalizer): tariff costs, storage simulation, net-metering, tariff comparison, RCE market prices, net-billing (RCEm/RCE deposit), optimal storage capacity, monthly summaries, CSV export. Architecture/flow/conventions are copied from omnis-mobile. License: GPL-3.0-or-later (port of eanalizer).

## Commands

The local toolchain (JDK 21 + Android SDK) lives outside the repo in `~/android-env/`. Always source it first:

```bash
source ~/android-env/env.sh && ./gradlew assembleDebug
source ~/android-env/env.sh && ./gradlew testDebugUnitTest            # single: --tests "com.theundefined.eanalizer.domain.AnalyzerTest"
source ~/android-env/env.sh && ./gradlew spotlessApply                # ktfmt kotlinlang style; CI runs spotlessCheck
source ~/android-env/env.sh && ./gradlew assembleRelease bundleRelease # needs RELEASE_* env vars, else debug signing
```

- Cut a release: `./release.sh [major|minor|patch|vX.Y.Z]` — bumps `versionName`/`versionCode` in `app/build.gradle.kts`, commits `release: vX.Y.Z`, pushes to `main`. Clean tree on `main` required. No local tagging.
- `local.properties` (`sdk.dir`), `*.jks`, `.env*` are local-only and gitignored.

## CI/CD (don't replicate manually)

`.github/workflows/build.yml`: every push/PR runs `spotlessCheck`, `testDebugUnitTest`, `assembleDebug`. A push to `main` whose HEAD message matches `^release: (vX.Y.Z)$` additionally decodes `RELEASE_KEYSTORE` to `eanalizer.jks`, builds signed `assembleRelease bundleRelease`, and creates the tag + GitHub Release with `eanalizer-mobile-vX.Y.Z-*.apk/.aab`. Keystore generated by `setup-keystore.sh` (alias `eanalizer`).

- After a successful release build, the `publish-play` job uploads the same signed `.aab` (passed as a workflow artifact) to the Play **internal** track via `.github/scripts/publish_to_play.py` (`--package com.theundefined.eanalizer`). Auth is keyless Workload Identity Federation (provider path and service account email are `google-play` environment secrets `GCP_WIF_PROVIDER`/`PLAY_SERVICE_ACCOUNT`, not in the repo; GCP pool `github`, provider `eanalizer-mobile`, trusting only this repo's ID + `refs/heads/main` + GitHub environment `google-play`), impersonating a dedicated service account (separate from omnis-mobile; its `workloadIdentityUser` binding is the `principalSet` for `attribute.repository_id` of this repo, not a `subject` — this repo uses GitHub's immutable OIDC subject format `repo:owner@id/name@id:...`, unlike omnis-mobile) that Play Console only allows to release to testing tracks of this app. The script is idempotent (already-uploaded/already-live versionCode is a no-op), so the job can be re-run. Release notes are generated from commit subjects since the previous tag (written in the app's default Play language, pl-PL). To (re-)publish an existing release manually: `gh workflow run build.yml -f tag=vX.Y.Z`. Python deps are hash-pinned in `.github/scripts/requirements.txt` (regenerate with `pip-compile --generate-hashes`); actions are pinned by commit SHA.

**`release.sh` and `build.yml` must stay in sync** when changing versioning, signing or the release flow.

## Build conventions

- Single module `app`, Kotlin DSL, no version catalog, versions inline. AGP 8.10.1, Kotlin 2.0.0, Gradle 8.12, JVM target 17, compileSdk/targetSdk 36, minSdk 26.
- `isMinifyEnabled = false` and `-dontobfuscate` are intentional.
- Dependencies are deliberately minimal: **kotlinx.serialization only (no Gson, no Retrofit)**, plain OkHttp, coroutines. No DI framework, no navigation library, no chart library (charts drawn with Compose `Canvas`), no Sentry.

## Architecture

MVVM + Kotlin Flow, single `MainActivity`, no navigation library — `MainScreen` switches views via `var currentScreen by remember { mutableStateOf("main") }`, `BackHandler` returns to `"main"`. One-way data flow: `EneaRepository` → `EanalizerViewModel` (`StateFlow<UiState>`, `SharedFlow<UiEvent>` for one-shots) → Compose UI.

```
app/src/main/kotlin/com/theundefined/eanalizer/
  domain/            pure Kotlin (java.time), NO android imports — CSV parsing, holidays, tariffs,
                     Analyzer (storage/net-metering simulation, tariff comparison, optimal capacity),
                     Periods, Aggregation, RceAnalysis, NetBilling + RcemParser, CsvExport
  data/local/        SettingsStore (prefs + EncryptedSharedPreferences), WebViewCookieJar, DataFiles
  data/remote/       EneaHtml (pure eBOK page parsing/URL rules, JVM-tested), EneaClient (customer
                     selection + CSV download on the WebView session), RceClient (PSE RCE per-day
                     cache, RCEm page cache 12 h)
  data/repository/   EneaRepository — orchestrates login, sync, persistence; exposes typed exceptions
  ui/                EanalizerViewModel, UiState
  ui/theme/          EanalizerTheme (Material3 light/dark, dynamic color on API 31+)
  ui/components/     Compose screens (MainScreen, AnalysisCards, ReportScreens: Compare/RCE/Monthly/
                     Data, TariffsScreen, SettingsScreen, EneaLoginScreen, Charts)
```

Key rules:

- **Layering**: `domain` must stay free of Android APIs so it can be unit-tested on the JVM. `data` depends on `domain`; `ui` depends on both. Repository throws typed exceptions (`SessionExpiredException`, `CustomerSelectionRequiredException`, `EneaProtocolException`, `IOException`); user-facing messages come from string resources in the UI.
- **Tests required for domain logic**: any change to `domain/` needs JUnit4 tests in `app/src/test/kotlin/com/theundefined/eanalizer/...`. Results should match the Python eanalizer for the same input.
- **Cache-then-refresh**: on start, show locally stored CSV data immediately, then sync in the background (pull-to-refresh = sync). Analysis is recomputed on `Dispatchers.Default` whenever records or prefs change — never re-download for a settings change. Preserve this pattern.
- **Login happens in a WebView** (`EneaLoginScreen`): since 10.2026 Enea protects the form with reCAPTCHA Enterprise, so the app never posts credentials itself. Stored credentials (encrypted, not hashed) only prefill the React form; the user submits and enters the 2FA code. Navigation is limited to https `*.enea.pl`; landing on the logged-in `ebok.enea.pl` finishes the login. OkHttp shares the WebView `CookieManager` via `WebViewCookieJar` (also HttpOnly/SSO cookies), and uses the WebView User-Agent. `SessionExpiredException` → show the login WebView again.
- **Port parity**: domain logic mirrors eanalizer (tariff zones G12 13-15/22-6, G12w peak 6-21; PSE `dtime` is the END of the quarter; net-billing rules in `NetBilling`). When eanalizer changes these, port the change with tests.
- **Strings**: `res/values` = Polish (default), `res/values-en` = English. Keep both files in sync whenever UI copy is added or changed; no hard-coded UI text.
- **Export** uses `FileProvider` (`${applicationId}.fileprovider`, `cacheDir/export/`) with `Intent.ACTION_SEND`.
- Run `spotlessApply` before committing; CI fails on formatting.
