# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

eAnalizer Mobile is a native Android app (Kotlin, Jetpack Compose/Material 3) that logs in to Enea eBOK, downloads hourly meter CSVs and analyses them like the Python [eanalizer](https://github.com/theundefined/eanalizer): tariff costs, storage simulation, net-metering, tariff comparison, RCE market prices, net-billing (RCEm/RCE deposit), optimal storage capacity, monthly summaries, CSV export. Architecture/flow/conventions are copied from omnis-mobile. License: GPL-3.0-or-later (port of eanalizer).

## Commands

The local toolchain (JDK 21 + Android SDK) lives outside the repo in `~/android-env/`. Always source it first:

```bash
source ~/android-env/env.sh && ./gradlew assembleDebug
source ~/android-env/env.sh && ./gradlew testDebugUnitTest            # single: --tests "com.theundefined.eanalizer.domain.AnalyzerTest"
source ~/android-env/env.sh && ./gradlew spotlessApply                # ktfmt kotlinlang style; CI runs spotlessCheck
source ~/android-env/env.sh && ./gradlew assembleRelease bundleRelease # needs RELEASE_* env vars, else debug signing
```

- Cut a release: `./release.sh [major|minor|patch|vX.Y.Z]` — bumps `versionName`/`versionCode` in `app/build.gradle.kts`, commits `release: vX.Y.Z`, pushes to `main`. Clean tree on `main` required. No local tagging.
- `local.properties` (`sdk.dir`), `*.jks`, `.env*` are local-only and gitignored.

## CI/CD (don't replicate manually)

`.github/workflows/build.yml`: every push/PR runs `spotlessCheck`, `testDebugUnitTest`, `assembleDebug`, and in parallel the `ui-tests` job: `connectedDebugAndroidTest` on an API 34 Pixel 6 emulator (`LocalFilesAppTest`, Polish UI via per-app locale: synthetic CSVs as imported files + local-only mode, so Enea is never contacted → costs equal eanalizer's, every report opens, RCE/RCEm are downloaded from PSE, net-billing in airplane mode doesn't crash; screenshots of each screen → artifact `ui-screenshots`). The RCE/RCEm tests need PSE to be reachable. `publish-play` also needs `ui-tests`; the GitHub Release itself is built in `check-and-build` and is not gated by it. A push to `main` whose HEAD message matches `^release: (vX.Y.Z)$` additionally decodes `RELEASE_KEYSTORE` to `eanalizer.jks`, builds signed `assembleRelease bundleRelease`, and creates the tag + GitHub Release with `eanalizer-mobile-vX.Y.Z-*.apk/.aab`. Keystore generated by `setup-keystore.sh` (alias `eanalizer`).

- Release builds also create the Sentry release `com.theundefined.eanalizer@<versionName>+<versionCode>` (same name the SDK reports) with the commit range previous tag..HEAD via `sentry-cli` (`--auto` associated nothing), so `Fixes EANALIZER-MOBILE-N` in a commit message resolves the issue once that release ships. Requires the Sentry GitHub integration (org `netrator`, repo added) and the `SENTRY_AUTH_TOKEN` repo secret (Sentry org auth token); without the secret the step is skipped, and it never fails the release.
- After a successful release build, the `publish-play` job uploads the same signed `.aab` (passed as a workflow artifact) to the Play **internal** track via `.github/scripts/publish_to_play.py` (`--package com.theundefined.eanalizer`). Auth is keyless Workload Identity Federation (provider path and service account email are `google-play` environment secrets `GCP_WIF_PROVIDER`/`PLAY_SERVICE_ACCOUNT`, not in the repo; GCP pool `github`, provider `eanalizer-mobile`, trusting only this repo's ID + `refs/heads/main` + GitHub environment `google-play`), impersonating a dedicated service account (separate from omnis-mobile; its `workloadIdentityUser` binding is the `principalSet` for `attribute.repository_id` of this repo, not a `subject` — this repo uses GitHub's immutable OIDC subject format `repo:owner@id/name@id:...`, unlike omnis-mobile) that Play Console only allows to release to testing tracks of this app. The script is idempotent (already-uploaded/already-live versionCode is a no-op), so the job can be re-run. Release notes are generated from commit subjects since the previous tag (written in the app's default Play language, pl-PL). To (re-)publish an existing release manually: `gh workflow run build.yml -f tag=vX.Y.Z`. Python deps are hash-pinned in `.github/scripts/requirements.txt` (regenerate with `pip-compile --generate-hashes`); actions are pinned by commit SHA.

**`release.sh` and `build.yml` must stay in sync** when changing versioning, signing or the release flow.

## Test data (no Enea needed)

- `app/src/sharedTest/fixtures/` is shared by JVM tests (resources) and instrumented tests (assets): `enea/2024.csv`, `enea/2025.csv` — synthetic, deterministic Enea exports (2024-10..2025-12, PV, holidays, DST gap, a 6-hour data gap; 2024.csv with BOM + CRLF) from `tools/testdata/generate_enea_csv.py`; `eanalizer-golden.json` — Python eanalizer results for them (tariffs, net-metering, 10 kWh storage, 2025 only, optimal capacity, monthly sums, net-billing RCEm/RCE with synthetic prices) from `tools/testdata/eanalizer_golden.py ~/programowanie/eanalizer` (run with eanalizer's `.venv/bin/python`).
- `GoldenDatasetTest` (JVM) asserts parity with that JSON. After changing the generator, regenerate both files. If a deliberate deviation from eanalizer changes a number, don't edit the JSON by hand — compute the expectation separately and document the deviation.

## Build conventions

- Single module `app`, Kotlin DSL, no version catalog, versions inline. AGP 8.10.1, Kotlin 2.0.0, Gradle 8.12, JVM target 17, compileSdk/targetSdk 36, minSdk 26.
- `isMinifyEnabled = false` and `-dontobfuscate` are intentional.
- Dependencies are deliberately minimal: **kotlinx.serialization only (no Gson, no Retrofit)**, plain OkHttp, coroutines. No DI framework, no navigation library, no chart library (charts drawn with Compose `Canvas`).
- Crash reporting: `io.sentry:sentry-android-core` only (no Sentry Gradle plugin — nothing to upload with minify off), auto-initialised from the manifest. The DSN is injected via `manifestPlaceholders["sentryDsn"]` from the `SENTRY_DSN` Gradle property/env var (GitHub secret `SENTRY_DSN`, Sentry project `eanalizer-mobile`, region `de.sentry.io`); empty DSN = Sentry disabled. `send-default-pii` is off.

## Architecture

MVVM + Kotlin Flow, single `MainActivity`, no navigation library — `MainScreen` switches views via `var currentScreen by remember { mutableStateOf("main") }`, `BackHandler` returns to `"main"`. One-way data flow: `EneaRepository` → `EanalizerViewModel` (`StateFlow<UiState>`, `SharedFlow<UiEvent>` for one-shots) → Compose UI.

```
app/src/main/kotlin/com/theundefined/eanalizer/
  domain/            pure Kotlin (java.time), NO android imports — CSV parsing, holidays, tariffs,
                     Analyzer (storage/net-metering simulation, tariff comparison, optimal capacity),
                     Periods, Aggregation, RceAnalysis, NetBilling + RcemParser, CsvExport + XlsxWriter,
                     Insights (day profile, heatmap, year-over-year, PV self-use estimate),
                     Costs (StorageEconomics, Bills, DynamicTariff), Billing (cost since the
                     settlement date, fixed fees prorated by days), DepositForecast (net-billing
                     deposits after the data end), Load (base load, peaks), ExtraLoad (heat pump/EV
                     what-if)
  data/local/        SettingsStore (prefs + EncryptedSharedPreferences), WebViewCookieJar, DataFiles
  data/remote/       EneaHtml (pure eBOK page parsing/URL rules, JVM-tested), EneaClient (customer
                     selection + CSV download on the WebView session), RceClient (PSE RCE per-day
                     cache, RCEm page cache 12 h)
  data/sync/         BackgroundSync + SyncJobService (platform JobScheduler, no WorkManager)
  data/repository/   EneaRepository — orchestrates login, sync, persistence; exposes typed exceptions
  ui/                EanalizerViewModel, UiState
  ui/theme/          EanalizerTheme (Material3 light/dark, dynamic color on API 31+)
  ui/components/     Compose screens (MainScreen, AnalysisCards, ReportScreens: Compare/RCE/Monthly/
                     Data, InsightScreens: Bills/Storage/YoY/Profile/SelfUse + DynamicTariffCard,
                     BillingScreens: BillingCard/BillingSettings/Deposit, LoadScreens: Power/
                     ExtraLoad, TariffsScreen, SettingsScreen, EneaLoginScreen, Charts)
```

Key rules:

- **Layering**: `domain` must stay free of Android APIs so it can be unit-tested on the JVM. `data` depends on `domain`; `ui` depends on both. Repository throws typed exceptions (`SessionExpiredException`, `CustomerSelectionRequiredException`, `EneaProtocolException`, `IOException`); user-facing messages come from string resources in the UI.
- **Tests required for domain logic**: any change to `domain/` needs JUnit4 tests in `app/src/test/kotlin/com/theundefined/eanalizer/...`. Where a feature exists in eanalizer, results should match it for the same input.
- **Cache-then-refresh**: on start, show locally stored CSV data immediately, then sync in the background (pull-to-refresh = sync). Analysis is recomputed on `Dispatchers.Default` whenever records or prefs change — never re-download for a settings change. Preserve this pattern.
- **Login happens in a WebView** (`EneaLoginScreen`): since 10.2026 Enea protects the form with reCAPTCHA Enterprise, so the app never posts credentials itself. Stored credentials (encrypted, not hashed) only prefill the React form; the user submits and enters the 2FA code. Navigation is limited to https `*.enea.pl`; landing on the logged-in `ebok.enea.pl` finishes the login. OkHttp shares the WebView `CookieManager` via `WebViewCookieJar` (also HttpOnly/SSO cookies), and uses the WebView User-Agent. `SessionExpiredException` → show the login WebView again.
- **Port parity**: domain logic started as a port of eanalizer (tariff zones G12 13-15/22-6, G12w peak 6-21; PSE `dtime` is the END of the quarter; net-billing rules in `NetBilling`) and the base rules should keep matching it. Since v0.1.7 the app is developed independently: features beyond eanalizer are welcome (e.g. net-billing carries deposits from up to 12 months before the period via `history`; with empty history results equal eanalizer). Document deviations in KDoc.
- **Main screen navigation**: reports are grouped (`NAV_GROUPS` in MainScreen: Costs / Consumption & production / Data) as `ListItem`s with icon + one-line description; configuration (tariffs, PV production, background sync) lives in Settings. Every report states which range it uses (selected period via `PeriodInfo`, or all data).
- **Ranges independent of the period**: `Analysis.sinceBilling` (from `AnalysisPrefs.billingDate` to the data end) and `Analysis.depositsNow`/`depositForecast` (net-billing, last 12 months to the data end) ignore the selected period; net-billing prices are fetched for the union of all ranges plus their 12-month history. The extra-load what-if runs on demand (`loadExtraLoad`, keyed by `forAnalysis` + `ExtraLoad`) and adds the load to the history too.
- **Report inputs**: `ReportPrefs` (PV production, storage price and physical parameters, dynamic margin) are kept outside `AnalysisPrefs` so editing them never re-runs `analyze()`.
- **Storage is a what-if only**: the main analysis, tariff comparison, bills and dynamic tariff always run with capacity 0 (meter data already includes an existing storage). Storage sizes are simulated only on the storage screen (`loadStorage`/`loadStorageDetail`, keyed by `StorageState.sim`). `SettingsStore.migrateStorageParams` moves the pre-v0.1.15 storage fields out of `AnalysisPrefs`. Cheap per-period results are part of `Analysis`; heavy ones (storage scenarios, dynamic tariff) run on demand and remember the `Analysis` instance they belong to (`forAnalysis === analysis`).
- **Data files**: `DataFiles` keeps Enea downloads as `filesDir/enea/<year>.csv` and user-imported CSVs (Settings → Data files, SAF picker) byte-for-byte in `filesDir/enea/imported/`; both are decoded with `EneaCsvParser.decode` (UTF-8/UTF-16/Windows-1250). Overlapping hours: the most recently written file wins. Switching customers drops only the downloads. **Local-only mode** (`SettingsStore.localOnly`) never contacts Enea: `sync` just re-reads the files, the background job skips, account/sync settings are hidden.
- **Background sync**: `EneaRepository.sync` is guarded by a process-wide `Mutex` (app + job). The job skips when data was synced today and notifies about an expired session only once (flag reset on login).
- **Demo mode** (`SettingsStore.demoMode`, `domain/DemoData`): synthetic, deterministic hourly data (household + 4 kWp PV) for Play reviewers (eBOK needs reCAPTCHA + 2FA), screenshots and trying the app. `EneaRepository.loadData` serves it instead of the data files; `sync` and the background job are no-ops while it is on; logging in or "Delete all data" leaves it.
- **Project site / Play listing**: `docs/` is the public GitHub Pages site (`index.html`, `privacy.html` — policy URL is in `privacy_policy_url`, linked in Settings; update the policy when permissions/network/Sentry behaviour change). Only `docs/plans/` and `internaldocs/` stay local. Store screenshots: manual workflow `screenshots.yml` runs `StoreScreenshotsTest` (androidTest, demo data, pl, light+dark, gated by `storeScreenshots=true`). The icon is adaptive (`mipmap-anydpi-v26`, vector foreground + monochrome); Play setup process: `~/programowanie/bracz/play-store-playbook/README.md`.
- **Strings**: `res/values` = Polish (default), `res/values-en` = English. Keep both files in sync whenever UI copy is added or changed; no hard-coded UI text.
- **Export**: share (`ACTION_SEND`) or save via SAF `CreateDocument`; XLSX written by the dependency-free `domain/XlsxWriter`. Sharing uses `FileProvider` (`${applicationId}.fileprovider`, `cacheDir/export/`) with `Intent.ACTION_SEND`.
- Run `spotlessApply` before committing; CI fails on formatting.
